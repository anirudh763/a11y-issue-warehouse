# PWA launch implementation

Preserve the current audit/profile work and domain engines. No deployment, fee, native project, framework or API change.

1. Inventory: CueReport has a network-first worker with unconditional activation and broad same-origin caching; replace that policy. Warehouse has no worker/manifest; add scoped public-only assets, including the existing DuckDB worker and Wasm extensions.
2. Generate app-specific real PNG icons and scoped manifests; preserve source/build ownership. Add one platform module for install, explicit preparation, update coordination, safe sharing, small optional checklist, feedback and factual trust disclosures.
3. Generate a SHA-256-pinned public asset list. Install atomically; never activate an incomplete shell, cache arbitrary requests or API responses, or delete other apps' caches. Keep updates waiting until explicit consent and other app tabs close.
4. Verify real controlled offline task/export and updates with service workers enabled at project subpaths; then account and UI regressions, mobile dimensions/axe and storage/negative cases. Record native-device tests as blocked if hardware is unavailable.

Scope: HTML/build/SW/platform CSS/JS, small domain success events, tests, docs and icons. No raw dataset or algorithm modifications.

Competitor decision: retain free public issue drafting (GitHub) and read-only reproducible SQL/export (Datasette). Existing teardown remains authoritative; no inferred vendor offline guarantee. Our local offline workflow is a testable distinction, not a claim of superior adoption.
